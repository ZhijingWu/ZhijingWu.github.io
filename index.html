Action-Conditioned World Model Planning Reliability — EgoWM Audit

Independent Audit / World Models & Planning Evaluation

How sensitive are action-candidate rankings to diffusion randomness, and does coupling that randomness stabilize their score differences?

I loaded the official EgoWM SVD 3-DoF navigation checkpoint and generated 24 eight-frame GPU rollouts: eight across four frozen actions and two seeds, followed by sixteen for a paired-sampling study.

  • Two-seed ranking change: final-frame LPIPS-Alex order changed from 1–0–2–3 to 0–2–1–3, with smaller image distance ranked first.
  • Verified noise coupling, unmet variance target: common-random-number (CRN) variance ratio R ≈ 0.785 exceeded the prespecified R ≤ 0.75 ceiling; the diagnostic bootstrap interval was approximately 0.026–1.585.

Scope. A local open-loop image comparison on one scene. No measured navigation success, physical action fidelity or new planning algorithm; the target variance reduction was not demonstrated.

Protocol, evidence & limitations — EgoWM

The official navigation checkpoint loaded successfully. Four fixed action sequences shared one initial image, one goal and an eight-frame horizon. Candidate 0 was the recorded sequence; Candidates 1–3 used local action perturbations. Seeds 0 and 1 produced eight rollouts in total, including the initial smoke rollout. The ranking reversal is an external LPIPS-Alex comparison, not evidence of model failure or a better plan.

The follow-up used Candidates 0 and 1 only with eight fresh seeds, 2–9, producing sixteen more rollouts. A same-seed probe verified the two pipeline noise draws, and both candidates ended with matching generator states for every paired seed. The scheduler added no step noise in this configuration.

Using sample variances with divisor n − 1, R = Var(L1 − L0) / [Var(L0) + Var(L1)] = 0.784736026168. The prespecified R ≤ 0.75 criterion was not met. A paired bootstrap of the eight seeds (10,000 resamples) gave a diagnostic interval of approximately 0.026–1.585, which includes 1; this is not a population confidence interval.

The result is limited to one context and locally perturbed actions. LPIPS distance does not measure physical action fidelity, calibrated uncertainty or navigation success. No successful variance-reduction method or new planner is claimed. The public repository provides the execution record, stored scores, coupling checks and reproduction instructions.

Sampling Efficiency and Geometric Sensitivity in Cardiff

Independent Inference Study / Diffusion Models

How does faster GPS sampling affect execution cost and trajectory geometry when first-stage conditions are fixed?

Using released Porto diffusion checkpoints, I compared GPS sampling intervals 20 and 50 across 64 conditions × 3 seeds, holding first-stage latents fixed within each seed.

  • 2.503× median paired-batch GPS-stage speedup across 24 batch pairs; conditional 95% bootstrap interval: 2.432–2.692×.
  • Core geometry: median length and pooled p95 step-distance point estimates met prespecified ±10% margins. Turning-angle tails and individual paths changed.

Scope. Independent, inference-only Porto study. Road validity and a full Cardiff benchmark reproduction were not established; no new diffusion algorithm is claimed.

Protocol, uncertainty & limitations — Cardiff

The first 64 valid attribute rows were evaluated with seeds 0, 1 and 2, yielding 192 trajectories per interval. Stage 1 latents were generated once per seed and reused in both GPS arms. Eight-row batches alternated timing order and restored the same pre-call RNG state per pair; synchronized GPS timings excluded setup, writing and Stage 1.

The speedup is the median of 24 paired-batch ratios, not an end-to-end acceleration estimate. Bootstrap intervals are conditional on the ordered subset and RNG coupling. Passing the frozen point-estimate margins does not establish population geometric equivalence.

The original stochastic sampler was retained. Shared draws entered different timesteps and coefficients, so schedule and noise-assignment effects were not separated. Turning-tail sensitivity was exploratory; smaller angles were not established as better.

No road graph, decoded routes, checkpoint-matched held-out reference or privacy evaluation was tested. The public aggregate package supports summary replay, not independent rederivation of withheld trajectory statistics or fresh model execution. This study is independent of the original Cardiff authors.

Execution-Reliability Diagnostics of Language Agent Tree Search

Independent Research Audit / Language Agents

Investigated action-output contracts and evaluator-score extraction in a pinned LATS/WebShop implementation using a bounded real-model execution trace, controlled frozen-prompt comparisons, and offline parser verification.

  • Action interface: 35/45 generated actions were invalid in the recorded baseline prefix. A format instruction changed syntax compliance from 0/15 to 15/15 completions; all were think[...], with no navigation demonstrated.
  • Score interface: complete final scores changed from 0/6 at 100 tokens to 6/6 at 300 tokens. The native parser agreed with only 3/6; the digit 5 in $50 explained all three mismatches.

Scope. One baseline task and selected frozen prompts. No benchmark-wide prevalence estimate, demonstrated task-success improvement, or real mixed-frontier child/value alignment exposure.

Study design, B1–B4 evidence & limitations
B1
In one bounded real-model baseline prefix, 35/45 generated actions were invalid, and 32/32 evaluator outputs lacked complete final scores at the 100-token cap. No successful purchase occurred. A request ceiling interrupted the first rollout before a completed backup.
B2
A command-format instruction changed syntax compliance from 0/15 to 15/15 completions. Each condition used 3 requests with 5 completions per request; the completions are clustered within requests. All 15 compliant outputs were think[...] commands. No navigation or environment episode was demonstrated.
B3
Across three frozen evaluator prompts and two repetitions per prompt/cap, complete final scores changed from 0/6 at 100 tokens to 6/6 at 300 tokens. These were fresh samples, not continuations. The native parser agreed with 3/6 complete scores; all three mismatches came from the digit 5 in $50. No search or environment episode was run in this comparison.
B4
81/81 private CPU checks passed: 64 synthetic cases, 12 recorded-response comparisons and 5 synthesis/boundary checks. The public repository provides only the 64 synthetic parser tests, not the full private real-response suite. Public raw real-model responses are withheld.

The public synthetic tests demonstrate source-level parser behavior; they do not independently reproduce the original real-model observations. Score-extraction agreement does not validate shopping judgments. Neither a new LATS algorithm nor an evaluated search-performance fix is claimed.

This independent audit is not affiliated with or endorsed by the LATS or WebShop authors. Its small selected sample and withheld raw responses limit generalization and public verification.

Full study description — ExpeL

Mechanism-Level Audit of ExpeL

I audited ExpeL as a follow-up to Memory-Collapse-Eval. In a deterministic shared-state EDIT replay, resetting inherited support moved the edited rule from rank 2 to rank 15 while preserving all 36 rule texts.

A controlled 50-task paired WebShop evaluation yielded 0/50 successes with inherited counts versus 1/50 with reset counts. This does not establish a reliable downstream benefit or equivalence between the policies.

One selected replay state and one rollout per memory/task limit generalization. Of 100 episodes, 96 reached the 10-round cap; trajectory observability also limited interpretation. Support counts are heuristics, not calibrated confidence.

Execution and Scoring Semantics in the Public AutumnBench Release

Independent Release Audit / Environment-Level Evaluation

Does submission preserve the selected historical answer, or can UI bookkeeping change its score?

I executed the pinned public Change Detection path in two released environments: 136 factorial scenarios, three path controls and eight paired original/changed replays, with 21,513 metered native calls.

  • Answer sensitivity: all 32 fixed-cost groups of four selected answers receive identical official scores; an index-only copied-object counterfactual changes 128/128 explicit-selection scores.
  • Browsing sensitivity: extra selection-only actions lower live scores in all 48 grouped comparisons, with the native history fixed.

Scope. Two deterministic public tasks, including an exploratory support-aware extension. Repeated seeds are not independent environments. No learned-agent ranking, general scorer repair or invalid published-paper result is established.

Execution record, target assumptions & limitations — AutumnBench

The public submission path replaces the selected historical index with an action-counter-derived value. All 136 scenarios follow that rule. Official runtime returns, an independent copied-index counterfactual and an observed-divergence target metric are retained separately. The latter target interpretation depends on the stated deterministic-original assumption.

The primary and conditional second-environment work was preregistered; the additional 32 support-aware scenarios were frozen after the first 104 were observed. These are executed scripted controls, not trained-model predictions or an independent population evaluation.

The earlier CPU MFP replay remains a separate historical result: 117/117 visible frame matches and a released planning witness reaching reward +1. Its old unretained Change Detection reward was not recovered. The continuation records fresh numeric returns and preserves all earlier evidence. The code used for the paper’s published results and the intended answer/target contract still require author clarification.

Communication-Cost Sensitivity in LLM Multi-Agent Protocol Assignment

Diagnostic / Sensitivity Study

Can measured local communication costs change a fixed protocol assignment—and predict workflow latency?

  • 480/480 requests succeeded. An eligible A2A → ANP reversal persisted after excluding Agora and separating forced candidate-set changes.
  • 120 workflows / 480 additional RPCs. Serial latency difference: predicted −0.156 ms, observed +0.828 ms; parallel comparisons were order-sensitive.

Scope. A controlled sensitivity diagnostic and separate within-session calibration; no established GAIA task-quality gain or general protocol superiority.

Full study description — ProtocolBench

Independent Study on ProtocolBench

I audited the released ProtocolBench / AgentProtocols GAIA routing path to ask whether workflow communication demand and measured runtime costs can change a fixed local protocol assignment.

I profiled A2A, ACP, ANP, and Agora over real local request paths with 1–100 KiB payloads; 480/480 measured requests succeeded. Under controlled communication demand, synthetic local preference margins, and released workflow configuration templates, I found an A2A → ANP assignment reversal in the declared sensitivity objective. The eligible reversal persisted in a no-Agora ablation after separating forced candidate-set changes.

In a separate workflow-latency calibration, I measured 120 no-op workflows (an additional 480 RPCs) with serial and fork/join execution. The within-session serial treatment-minus-baseline latency was predicted as −0.156 ms but observed as +0.828 ms; parallel comparisons were sensitive to execution order.

Assignment sensitivity and workflow calibration are distinct results; neither establishes GAIA task-quality gains or general protocol superiority. The linked public artifact documents the assignment diagnostic.
